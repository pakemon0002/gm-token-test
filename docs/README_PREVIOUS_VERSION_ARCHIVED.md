# GM TOKEN — игровая Telegram Mini App (аудиторская исправленная сборка v3.0, проверка перед размещением)

**Статус:** исходники интерфейса + серверный движок виртуальных GM/CR + автоматические тесты. **Не размещено на хостинге, не подключено к действующему Telegram-боту, не готово для публичного запуска без проверки владельцами.** Нет операций с реальными деньгами. Все активные игровые операции выполняются сервером, а не путём изменения JavaScript-состояния.

## Содержимое

- `miniapp/src/main.tsx`, `miniapp/src/styles.css` — React/TypeScript, Light/Dark, главные страницы и дополнительные Mining, Vault, Shop, Boxes, Support, Admin.
- `miniapp/public/` — автономный тестовый UI с 216 **оригинальными** PNG-иконками (54×4), двумя исходными логотипами и компилированным JS.
- `server/index.mjs` — Node.js HTTP, SQLite, HMAC-проверка Telegram `initData`, серверная регистрация, RBAC, тикеты, 2FA, журнал и фонды.
- `server/game.mjs` — Mining, Vault/Holding, рефералы, задания и XP, GM Boxes, GM Shop, стартовый аукцион, Limit/Market Order, учёт комиссий, POINTS, защита от самоторговли, учёт эмиссии.
- `server/bot.mjs` — команды `/start` и `/help`, открытие Mini App через `BOT_USERNAME=gm_token_test_bot` и `PUBLIC_APP_URL`. Реальный токен не включён.
- `tests/` — 24 автоматических сценария (14 новых после аудита), в том числе живые HTTP-запросы к тестовому серверу с HMAC-подписью.
- `docs/` — оригинальные светлый и тёмный эскизы, API, результаты визуального аудита, решения, требующие согласования.

## Что действительно работает

- Telegram-подписанная регистрация, **5000 CR однократно** (пока хватает Welcome Pool), роли двух равноправных владельцев и назначенных ими модераторов.
- Фиксированная эмиссия **150 млн GM и 1 млрд CR**, атомарные транзакции SQLite и учёт резервов в сотых долях.
- Автоматическое Mining по уровню/Power/Storage/Efficiency/Holding Boost, Claim ≥1 GM, +20 XP один раз в UTC-сутки, расход из ограниченного Mining Pool.
- Вклад и вывод Holding, комиссия 5%, один вывод в UTC-сутки, накопление по фактическому времени, ежечасное распределение при разрешённой ставке и наличии средств, Claim, одноуровневые 25%-реферальные награды только от фактического Holding Claim.
- Стартовый 24-часовой аукцион заявок, далее Limit и Market ордера с защитой проскальзывания 3%, сроки действия, частичное исполнение, комиссионные 0,5% в получаемой валюте, возврат остатков, 10 создания/редактирования в 60 секунд, 100 активных заявок, запрет самоторговли.
- POINTS за исполненный торговый объём (10 за 10 000 GM, до 1000 в UTC-сутки), трата POINTS на GM Boxes из ограниченного пула, когда владельцы утвердят размер наград.
- GM Shop с комиссией 1% GM и подтверждением суммы CR перед обменом, когда владельцы утвердят **формулу динамического курса**.
- Задания и достижения: настраиваемый серверный каталог, проверяемые условия, однократное начисление GM/XP; нельзя повторно получить награду одной операцией.
- Support Center: тикеты, категории, два автоматических шага, очередь, ручной выбор модератора, возврат через 12 часов без первого ответа, закрытие обычных решённых тикетов через 48 часов, апелляции человеку.
- Admin: роли (Owner/Co-Owner, Moderator), 2FA для балансов и переводов между фондами, ограничение источников переводов Treasury/Future, корректировка ошибок по тикету, аудит, сверка supply.

### Незавершённые **решения владельцев** — поэтому функции безопасно выключены

Система **не** притворяется, будто следующие параметры утверждены. Точные цифры и правила обозначены в [`docs/OPEN_DECISIONS.md`](docs/OPEN_DECISIONS.md).

1. Полная формула рыночного курса GM Shop. Пока `SHOP_RATE_MODE=disabled`; `median95` существует **только как тестовый кандидат**.
2. GM-награды за Bronze/Silver/Gold. Пока `BOX_REWARDS_GM_JSON={}`; суммы 15/45/105 — **только пример для тестов**, не окончательная экономика.
3. Ставка Holding **в пределах** утверждённого потолка 0,5% в день. Пока `HOLDING_DAILY_BPS=0` (наград не начисляет).
4. Величина Daily Reward и полный набор заданий, достижений, XP. По умолчанию Daily Reward отключён, каталоги пусты, но серверные механизмы готовы.
5. Срок действия POINTS, точный tie-break стартового аукциона, расширенная защита от coordinated wash trading, политика ограничения фондовых изменений двумя совладельцами.

Отключение неподтверждённых параметров — не программный сбой. **Полноценный экономический запуск потребует их утверждения и повторных тестов.**

## Локальный запуск (при необходимости)

Требуется Node.js 22+ (экспериментальный `node:sqlite`).

```bash
npm test
npm run start:env
# либо, если .env не создан: npm start
```

Для подключения Telegram нужен HTTPS-адрес и переменные `BOT_TOKEN`, `OWNER_TELEGRAM_IDS`, `OWNER_TOTP_SECRETS`, `PUBLIC_APP_URL` из `.env.example`. После запуска сервера: `npm run bot:env` для polling **или** `BOT_POLLING=1` вместе с сервером; не запускать оба варианта одновременно. При входе через Telegram приложение передаёт *сырой* `initData` в заголовке `Authorization: tma ...`, сервер проверяет HMAC. Секрет бота и TOTP **никогда** не помещаются в клиентский код.

Вне Telegram демонстрационный интерфейс доступен по `http://localhost:8787/`, но **не имитирует реальные начисления**: пользователь должен открыть Mini App через проверенный Telegram-контекст.

### Тесты и компиляция

```bash
npm test
# при наличии TypeScript CLI:
tsc -p miniapp/tsconfig.standalone.json
node --check server/game.mjs
node --check server/index.mjs
```

Тестирование выполнено на изолированных временных SQLite-базах с фиктивным токеном Telegram. Никакие реальные пользователи, кошельки, деньги или бот `@gm_token_test_bot` в тестах не затронуты. Фактические серверные сценарии описаны в [`docs/QA_RELEASE_CHECKLIST.md`](docs/QA_RELEASE_CHECKLIST.md).

## Ограничения и запуск позже

- **Не выкладывать секреты в GitHub**, даже в приватный репозиторий, и не публиковать файл `.env`.
- SQLite на бесплатном Render без постоянного диска **может потерять данные после перезапуска**. Перед тестом с постоянными аккаунтами нужен persistent volume либо перенос на PostgreSQL; для Render+Neon необходима адаптация драйвера с транзакциями и повторные нагрузочные тесты.
- Offline preview использует поставляемый старый React UMD с адаптером хуков. Перед публичным запуском нужно перейти на поддерживаемые React/Vite-версии, собрать production bundle и протестировать WebView iOS/Android.
- Статический график свечей до накопления истории OHLC помечен **демонстрационным**, цена сделки берётся с сервера; демоданные не выдаются за реальные.
- **Нет настоящей блокчейн-монеты, обмена на реальные деньги или гарантированного дохода.** GM/CR исключительно внутриигровые баллы.
- Автотесты не означают отсутствия всех багов. Нужны ручные тесты на настоящем Telegram WebView, конкурирующие пользователи, сбои сервера, восстановления из бэкапа и внешняя проверка безопасности до открытого запуска.
