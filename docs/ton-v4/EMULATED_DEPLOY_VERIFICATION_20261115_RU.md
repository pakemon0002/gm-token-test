# GMTEST — проверка виртуального развёртывания в Acton TVM

Дата: 15 ноября 2026. **Только эмулятор TON. В публичной TON Testnet ничего не развёрнуто.**

## Проверенный результат

CI запускает **официальный Acton 1.2.1**, создаёт временный шаблон `jetton`, вносит отдельные GMTEST-ограничения в Jetton Master, затем:

1. `acton build` и `acton check` — успешно.
2. `acton test` — **54 из 54 тестов успешно**; семь тестовых файлов.
3. `acton run deploy-emulation` — успешно создал **виртуальный** Jetton Master и выполнил getter-проверки:
   - `JETTON TOTAL_SUPPLY=0` (в начале нет выпущенных токенов);
   - `JETTON MINTABLE=true` (эмиссия до её окончательного отключения разрешена);
   - `JETTON METADATA_name=GM TOKEN TESTNET`;
   - `JETTON METADATA_symbol=GMTEST`;
   - `JETTON METADATA_decimals=9`;
   - admin — временный кошелёк, существующий **только в эмуляторе**.
4. Дополнительно CI сохраняет локальные SHA256 собранных файлов и log виртуального deploy, не включая seed, закрытые ключи, сохранённые сессии или адреса реальных кошельков.

**Подтверждение GitHub:** https://github.com/pakemon0002/gm-token-test/actions/runs/43722655780

**Артефакт GitHub Actions:** `gmtest-acton-1.2.1-emulator`, в течение 7 дней. В нём содержатся файлы build, `gmtest-deploy-emulation.log` и `gmtest-emulator-artifact-hashes.txt`. Эти файлы НЕ являются транзакцией TON.

## Проверка неизменяемой эмиссии

Изменённый тестовый minter блокирует mint свыше 150 000 000 GMTEST одновременно в обращении и запрещает upgrade кода и данных. Дополнительные сценарии доказывают в TVM-эмуляторе:

- разрешён выпуск ровно 150 млн;
- попытка превышения на одну raw-единицу отклоняется;
- если **полностью выпустить 150 млн, затем отозвать admin**, даже последующий burn не позволяет выпустить новые GMTEST;
- назначенный заранее `nextAdmin` после отзыва admin **не может** вернуть права выпуска; прежний admin тоже не может их восстановить.

**Важно:** эти тесты не означают, что 150 млн действительно выпущены. В актуальном запуске deploy-emulation начальная эмиссия **0**, а выпуск и отзыв admin проверяются **отдельными изолированными сценариями**. Безопасность для публичной сети не подтверждена независимым аудитом.

## Что блокирует публичный TON Testnet

- Нет принадлежащего владельцу отдельного **Testnet-кошелька**, готового подтверждать тестовые транзакции. Адрес, напечатанный эмулятором, нельзя использовать в TON Testnet: он относится только к локальной виртуальной сети.
- Реальный Jetton Master адрес в Testnet отсутствует. Поэтому нельзя достоверно утверждать, что токен там существует, а также публиковать «адрес токена» из эмулятора.
- Реальный GM, обеспечение 1:1 и любые операции Mainnet по-прежнему отключены. GMTEST создаётся исключительно для разработки, без денежной стоимости.

### Следующий шаг при появлении тестового кошелька

Отдельно, с контролем сети **Testnet (-3)** и подтверждением владельца, проверить тестовый deploy; после него сверить фактический Master и metadata только через чтение TON Testnet. **Не передавать никому 24 слова и не вносить их в GitHub/Render.**

До появления такого кошелька автоматическое развёртывание в публичной сети запрещено.
